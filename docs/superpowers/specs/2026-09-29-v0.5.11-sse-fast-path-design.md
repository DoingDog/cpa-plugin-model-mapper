# v0.5.11 SSE fast-path model restoration spec

## Intent and scope

Fix a plugin-owned stream response bug: when one host read contains a complete SSE event whose JSON `model` key is Unicode-escaped and whose colon is in the next `data:` field, the outer fast path forwards the upstream model unchanged. Preserve the client's requested model in the existing whitelisted response fields. Do not modify CPA, the request mapping DSL, the SSE protocol, or unrelated response fields.

## Observed failure

With the selected client model `client`, a complete event whose first line consists of `data: {"`, one byte `0x5c` (backslash), and `u006dodel"`, followed by `data: :"upstream"}` and an empty line, joins into valid JSON with `model = upstream`. `newSSERewriter("client")` restores the field, but `streamChunkRewriter.Write` skips that parser when its raw-byte marker scan misses the key across the second `data:` prefix. The output depends on whether the host reads the event whole or in parts.

## Design

Keep the existing complete-SSE passthrough for frames safely proven not to contain a model key, including large batches of escaped but unrelated text. Scan only SSE `data:` values with the existing response-model marker scanner when the raw-byte check finds no model field but the frame contains an ASCII JSON Unicode escape (`\u00`); neither ordinary escapes such as `\n` nor Unicode escapes for non-ASCII characters can encode any letter of `model` or `modelVersion`. Feed one newline between data fields and reset at event boundaries. If that scan finds an escaped model key, use the existing `sseRewriter` to join data fields and restore the model. Do not alter raw JSON rewriting, unrelated SSE event fields, framing, header policy, or cross-frame state.

## Acceptance criteria

1. A focused outer `streamChunkRewriter` regression test fails before the fix and passes after it: one complete multi-data SSE host read with a Unicode-escaped model key emits `data: {"model":"client"}` with the original event framing retained.
2. The same event split across host reads still restores the model; unrelated escaped JSON fields and SSE metadata remain unchanged.
3. Existing tests, race tests, vet, plugin registration tests, script tests, packaging/compatibility checks and build CI pass. The complete-SSE batch fast path without model markers retains its existing allocation limit even when unrelated JSON text contains backslash escapes; benchmark ordinary and non-ASCII Unicode-escaped text batches to detect CPU regressions.
4. Publish only after review and verification: patch tag `v0.5.11` from local `main`, pushed to GitHub to trigger the release workflow.

## Exclusions

Gemini `:countTokens` cannot be safely distinguished from non-streaming generation through CPA v7.2.152's wildcard `request_path` and there is no host count callback. CPA v7 host callback HTTP status loss is upstream-owned. A bare Interactions JSON event without `event:` was not found on normal CPA stream producers. Do not change any of these paths without evidence of a safe plugin-only fix.
