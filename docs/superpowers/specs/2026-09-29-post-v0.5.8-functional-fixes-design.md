# v0.5.8 后插件功能缺陷修复设计

## 目标和依据

本次只修改 model-mapper 插件仓库。目标是修复已确认的调用者凭据绑定和自定义构建目录问题，不增加规则语法或新的模型功能。基线为 `main` 的 `2f9bc41`、`v0.5.8`；初始未跟踪的 `.claude/` 不属于本次工作。扫描覆盖 `main.go`、ABI、测试、Makefile、发布脚本、CI、插件相关 CPA 宿主代码及公开协议。基线 `go test ./...`、三个脚本测试对、`go vet ./...` 和相应 `-race` 检测通过，因此必须先新增能失败的聚焦测试，再改实现。

## 必须修复的行为

### 1. executor 不可把其他请求的 caller 缓存当成当前凭据

`main.go:3029-3046` 缓存键只有 `caller_scope` 和 pattern。route RPC 对无绑定原始凭据拒绝缓存命中，两个 executor RPC 路径却允许无凭据复用全局布尔结果。例：规则 `foo=>bar;key*#bar=>baz`，请求 A 以 `key123` 绑定同一 scope 种下肯定缓存；请求 B 由自定义 CPA access provider 返回同一 Principal，却不在自身 headers/query 中提供该原始凭据。B 的 route 得到 `bar`，executor 可能错误地调用 `baz`。CPA 插件协议没有 route 和 executor 共用的可信请求 ID；`host_callback_id` 每次调用重新分配，不能用于关联。

修复采用可靠的 fail-closed 边界：两阶段均仅在**当前 RPC** 的 headers/query 中找到与 `caller_scope` 摘要匹配的原始凭据时，才评估或复用 wildcard caller pattern；没有凭据时，正向和反向 scoped entry 均跳过，unscoped rules 仍可执行。保留已认证调用者的缓存优化。对 route 与非流/流 executor 分别回归验证。现有测试允许 route 后 interceptor 删除或替换凭据仍应用 wildcard scoped entry；在缺少可信阶段关联的 CPA ABI 下，该保证与跨请求安全无法同时成立。测试和 README 必须改为明确当前请求的凭据要求，不得用 TTL、请求体哈希或不可信 metadata 伪装关联。

### 2. 自定义 `DIST_DIR` 的构建、smoke 和清理一致

`Makefile:95` 在 `smoke-local` 构建自定义 `DIST_DIR` 后运行 helper，`.github/scripts/smoke-local.go:168` 却固定从 `<repo>/dist` 复制插件。应把 Makefile 的实际 `DIST_DIR` 传给 helper；helper 独立运行时继续使用默认 `dist`，相对路径以仓库根目录为基准，绝对路径不拼接仓库根目录。回归测试必须证明自定义目录优先于已有旧 `dist` 产物，且默认路径不变。

`Makefile:84,89` 的两条安装命令须引用含空格 `DIST_DIR` 的源路径；`Makefile:125` 的 `clean` 须只删除**完整的**目标目录，而不是把带空格的目录名拆成多个 `rm` 参数。只通过 `make -n` 和隔离临时目录测试清理展开，不对用户的真实目录执行带风险的命令。

## 明确不在插件侧猜测修复的边界

- `matchTokens` 首次字面量匹配不回溯是既有 DSL 语义。README 明确写明该规则，`TestApplyRulesCharacterSemantics` 的 `wildcard does not backtrack` 用例也要求保持；重复后缀漏匹配的扫描候选并非 bug，不改 matcher。
- Gemini `countTokens` 与 `generateContent` 共用 CPA Gin 模板 `/v1beta/models/*action`；router 看不到 action，映射后的 count 需要 `executor.count_tokens`，但 host 没有原生 count callback。仅修改插件无法既保留非流 Gemini 映射又正确路由计数；不以禁用全部非流映射或伪造计数值代替修复。需要 CPA 将 action 与计数能力明确传给插件。
- CPA HomeEnabled 状态下 self/executor route 返回 503，但 route request 不携带此状态。插件无法据此可靠绕过；需要 CPA 宿主支持或暴露状态。
- 公开 issue #8 报告 `/v1/responses` 映射流返回空流。现有插件先处理携 `Done=true` 的 payload 再 flush，CPA 正常 host stream chunk 也不提前标记完成；目前没有实际 host read payload 和 event framing 可以定位故障，因此不修改流实现，不声称修复该 issue。
- 未发现经证实的新功能需求或性能瓶颈；不增加新功能，不进行无基线的性能优化。保持 ABI/插件注册、现有协议和发布产物格式不变。

## 验收

1. 新增聚焦 Go 测试验证缓存和 smoke 目录问题，`make -n` 验证安装与清理命令；修复前测试/命令检查失败，最小修复后通过；原有插件与三个脚本测试对、`go vet ./...`、`go test -race ./...` 均通过。
2. 验证插件注册响应、C ABI 边界、真实 CPA 注册集成测试，及现有 CI 构建流程；需要在线模型密钥的 live smoke 若环境未提供则明确记录未运行。
3. 检查改动仅限本次修复及必要的测试/README/spec/plan；最终合并本地 `main`，以新的补丁版本发布并推送 GitHub，由标签触发所有平台的自动构建与发布，核对 CI 和产物结果。
