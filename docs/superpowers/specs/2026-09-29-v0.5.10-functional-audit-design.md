# v0.5.10 功能审计修复设计

## 目标与边界

本次只修复两项已复现的插件仓库缺陷：分片 raw JSON 流产生二次方级处理开销，以及本地 smoke helper 把 CPA 关闭时的异常退出记为成功。保持 CPA v7.2.152 的插件 ABI、现有路由与模型改写语义不变；不修改 CPA 本体，不扩大配置或协议支持范围。扫描基线为 `551e2361a6caeb0734e49cb1a8596000e5d6e6f1`、`v0.5.9`。原有未跟踪 `.claude/` 不是本次改动。

### 已确认事实

- `main.go` 的 `streamChunkRewriter.Write` 每次将待完成 JSON 前缀与新 payload 拼接；`retainPending` 再复制整个前缀。raw JSON 和 Gemini 数组元素还从开头重复扫描。合法的 8 MiB 对象按 8 KiB 分片累计分配约 9.0 GiB；合法的 8 MiB Gemini 数组元素按相同分片累计分配约 9.1 GiB、耗时约 26 秒，单次输入该数组元素约 0.18 秒。两种输入都低于现有 16 MiB 待完成单位上限。已在仓库外 Go overlay 复现，未改动仓库。
- `.github/scripts/smoke-local.go:369-374` 在成功发送 `os.Interrupt` 后从 `waitDone` 收到非零退出却直接返回 nil；若退出是 CPA 关闭/插件卸载故障，`runCase` 因此误报 smoke 成功。测试代理在系统临时目录用 `exit status 2` 复现。`:399-403` 在杀进程竞态中也会忽略部分已经退出的异常状态。

## 流式 JSON 处理

`streamChunkRewriter` 在识别正在接收的 raw JSON 对象、数组或数组元素后，持有自己的待处理字节缓冲。后续 `Write` 只追加本次分片，并从上次扫描停止处继续跟踪 JSON 字符串、转义和嵌套闭合状态；未完成时不重新解析整个前缀。单位完成时再调用现有 JSON 校验、模型字段恢复和分帧/输出路径。所有已知非 JSON、SSE、分隔符及异常输入仍走现有行为。优先复用既有重写函数，不改变模型字段白名单。

必须维持：输入 payload 可能在 `Write` 后被宿主复用；待处理数据不能引用该可变输入；只有当前未完成单位计入 16 MiB 上限，完成单位可以持续输出；Gemini 数组逐元素输出而非等全数组；完整前缀在不完整尾部之前输出；SSE framing、`[DONE]`、`Flush` 对不完整 framed JSON 的报错、原始 JSON 空白分隔符及已有错误传播保持原样。

回归用例使用同一合法对象和数组元素分别单次输入、分片输入，校验模型恢复和字节结果一致，并断言固定分片数量下的分配次数不会随分片数线性增加；性能基准显示实际耗时及 B/op，不用不稳定的绝对耗时作为单元测试断言。覆盖转义引号、嵌套对象、跨分片闭合、输入缓冲变更以及完成值后的未完成尾部。

## 本地 smoke 退出判定

`stopCPA` 在发送中断后读取 `waitDone` 返回的错误。正常退出、由本次中断直接终止的预期信号退出继续算正常；普通非零退出通过现有 `earlyExitError` 连同日志报告。等待超时后主动杀进程仍保留现有跨平台清理行为；若 `Kill` 表明进程此前已经退出，则同样检查真实退出状态，而不是吞掉异常。不要把 Windows 上无法发送 `os.Interrupt` 后的正常强制终止误判为 CPA 崩溃。

定向测试包含中断后 `exit status 2` 的失败回报、预期 SIGINT/正常退出的成功、`Kill` 与异常退出竞态，以及现有 Windows/Unix 终止测试。`runCase` 继续通过 `errors.Join` 汇总请求与清理错误。

## 排除项

Google Interactions API 的 `agent` 有效类型是字符串枚举；CPA 对 object 等输入的宽松解析不使其成为有效请求，故不改 `interactionsUsesAgent`。CPA 的 Home 模式会主动拒绝插件 executor 路由且没有提供本插件可用的 Home 标志，不在插件中绕过宿主限制。正常 Gemini `alt=sse` 在 CPA v7.2.152 被转为空 `Alt`；未证实其他非空 Alt 成功返回非 JSON 流，故不改 Content-Type 推断。`shutdownExecutorStreams` 已等待在途工作者，不改生命周期。既有 ABI、发布包格式和响应字段白名单不变。
